## Revision, repeatability and verification roles

The implementation is the current worktree over
`dd4510fa0f42dc436da6d17e476cbc91dba593fe`; no commit or remote CI result is claimed.
The source audit hashes all 294 non-generated compiler/CLI modules. Each slice's
conformance records separately pin its source, selected profile, tools, supplies and
artifact evidence; earlier process/fault reports retain their original provenance.
The finalized Native OS Integration Plan numbers workstreams WS-02 through WS-30
(with WS-24 service subdivisions), and SPEC-01 through SPEC-03; it has no WS-01.
All of those obligations are represented above.

From the repository root, run:

```sh
node packages/compiler/scripts/check-native-migration-audit.mjs
node packages/compiler/scripts/check-native-migration-audit.mjs --artifacts
```

The first command verifies complete source coverage, reviewed bytes, removed actors,
retired implementation names and absence of source-provider spelling recognition.
The second additionally requires every preserved local native/Wasm report, verifies
its recorded identity, and repeats the exact native symbol/Wasm export checks.
Missing reports and changed evidence fail; there is no skipped-lane success path.
These checks complement the semantic/root/bootstrap tests, documentation generators
and conformance receivers. They do not alone establish compiler privilege correctness.

The required CI supply matrix in `.github/workflows/ci.yml` includes Darwin ARM64,
GNU Linux x86-64 and GNU Linux ARM64. It runs the real/fault process, hosted-start,
host-input, report and storage runners, plus Wasm on the x86-64 GNU job and raw Linux
on both GNU jobs. Every runner fails for missing designated supplies. The recorded
local native results include compilation, linking, object inspection and execution
for all three targets; raw Linux records both architectures in both optimization
modes. This is a configuration-to-local-evidence comparison, not an assertion that
a new remote CI run has completed.

Debug/optimized lanes use optimization `none`/`speed`. LTO is unsupported: the typed
profile accepts no LTO option, helper admission declares `lto: unsupported`, and
NativeLinkResolver rejects required linker plugins. None of these reports claims
LTO execution. Managed toolchain downloads remain deferred under WS-17/JUL-126;
only explicit pinned user-provided supplies are admitted here. Later raw facilities
(PIE relocation, dynamic loading, TLS/constructors, raw process spawning, execution
storage and terminal-report support) remain outside JUL-136's static non-PIE slice.
