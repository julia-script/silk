# Design — add-language-package

## Context

See proposal.md for motivation. Constraints that shape the approach:

- The compiler's lexer is byte-oriented: `Lexer.lex(SourceFile.make(id, bytes))` returns tokens
  whose spans are **UTF-8 byte offsets** ([Lexer.ts](../../../packages/compiler/src/Lexer.ts),
  [SourceFile.ts](../../../packages/compiler/src/SourceFile.ts)). CodeMirror decorations address
  **UTF-16 code units**. These coincide only for ASCII documents.
- The workbench source pane ([workbench.tsx](../../../apps/docs/app/labs/workbench.tsx),
  `SourceBody`) is a controlled `<textarea>` wired to atoms: `modulesAtom` (source text),
  `cursorAtom` (byte-range span cursor set from `selectionStart`/`selectionEnd`). URL state
  encodes the source.
- Docs code fences are highlighted by Shiki via `rehypeCodeOptions` in
  [source.ts](../../../apps/docs/lib/source.ts); a `fallbackLanguage: 'text'` already handles
  unknown fences.
- Monorepo conventions: strict TypeScript, ESM-only, actor-module style (one concept per module,
  data-first functions), `@effect/vitest` for Effect tests / plain `it` + `assert` for pure tests,
  Changesets + release-candidate validation for publishable packages.

## Goals / Non-Goals

**Goals:**

- One source of truth per concern: the compiler lexer drives CodeMirror; one tmLanguage JSON drives
  Shiki and Cursor.
- Zero-ceremony local Cursor install; nothing new enters the publish pipeline yet.

**Non-Goals:**

- Lezer grammar, code folding, indentation logic, autocomplete, diagnostics-in-editor, LSP.
- tree-sitter (own toolchain; later change).
- Marketplace/OpenVSX packaging (`vsce`), extension icons, snippets.

## Decisions

### 1. Lexer-driven CodeMirror highlighting (no Lezer grammar)

A `ViewPlugin` re-lexes the full document on every change and emits a `DecorationSet` mapping each
token to a style class via `TokenKind`.

- **Why not a Lezer grammar:** it is a second definition of Silk that drifts; the real lexer is
  already browser-safe TypeScript and definitionally correct (`Invalid` tokens give error
  highlighting for free).
- **Why full re-lex, not incremental:** the lexer is a 277-line single pass; workbench programs are
  tiny. `ponytail:` full re-lex per edit, incremental lexing if documents ever grow past ~100 KB.
- **Styling:** map `TokenKind` → `@lezer/highlight` `tags` and export a `HighlightStyle`-based
  theme entry point, so the package plays nicely with CodeMirror theme conventions while staying
  grammar-free. Doc comments get `tags.docComment`, invalid tokens get a dedicated error class.

### 2. Byte↔UTF-16 offset mapping

Token spans are byte offsets; decorations need UTF-16 offsets.

- ASCII fast path: if `TextEncoder` output length equals the string length, byte offsets are used
  directly.
- Otherwise build a byte→UTF-16 prefix map once per lex (single pass over the encoded document) and
  translate each span. Non-ASCII bytes lex as `Invalid`, but their spans must still land on the
  right characters.

### 3. Package layout — `packages/language`, subpath exports

Following the repo's stable-public-subpath convention:

```
packages/language                 @silk-lang/language
  src/CodeMirror.ts               extension factory + highlight theme (actor module)
  src/TextMate.ts                 grammar + language configuration (the source of truth)
  scripts/sync-vscode.mjs         generates the extension's JSON files from dist/TextMate.js
  test/CodeMirror.test.ts         token→decoration mapping, offset mapping (pure `it` + assert)
  test/TextMate.test.ts           keyword-sync + drift tests + scope assertions via shiki
```

As implemented, the grammar's source of truth is TypeScript, not JSON: `src/TextMate.ts` builds
the keyword alternations from a `Record<KeywordKind, string>` that is type-exhaustive over the
compiler's `TokenKind`, so compiler keyword changes fail this package's typecheck. The JSON files
exist only inside `packages/vscode`, generated by `sync:vscode` and drift-checked by a test —
stronger than hand-maintained JSON, and it sidesteps NodeNext JSON-import attribute friction
across tsc, vitest, and Next.

CodeMirror packages (`@codemirror/state`, `@codemirror/view`, `@codemirror/language`,
`@lezer/highlight`) are **peer dependencies** (single-instance libraries; the consuming app owns
the version) and dev dependencies for tests.

- **Alternative considered:** shipping the grammar inside the docs app — rejected; the same file
  must serve Cursor, and `packages/language` is the long-term home for tree-sitter-adjacent
  exports too.

### 4. Keyword-sync test derives keywords from `TokenKind`

The compiler does not export a keyword list, only the `TokenKind` union
([Token.ts](../../../packages/compiler/src/Token.ts)). The test lexes each candidate keyword
string and asserts it produces the matching `<Name>Keyword` token — deriving truth from lexer
behavior, not from a hand-copied list. It then asserts the tmLanguage keyword alternation equals
that set exactly (both directions).

- **Alternative considered:** exporting `keywords` from the compiler — unnecessary API surface;
  behavior-derivation needs no compiler change.

### 5. Shiki wiring

Add the grammar to `rehypeCodeOptions.langs` in `apps/docs/lib/source.ts` by importing the JSON
from `@silk-lang/language`. Shiki accepts raw TextMate grammar objects in `langs`; existing
`fallbackLanguage` behavior is untouched.

### 6. Workbench editor swap

`SourceBody` replaces the `<textarea>` with a CodeMirror `EditorView` (thin React wrapper local to
the workbench — no new React-CodeMirror dependency):

- `updateListener` writes doc changes to `modulesAtom` (same shape as today).
- Selection changes with a nonempty main range set `cursorAtom` — converting UTF-16 selection
  offsets **to byte offsets** (inverse of the decoration mapping) since the span cursor is
  byte-addressed.
- Switching the active module replaces the editor state; external resets (URL/preset loads) are
  reconciled by comparing doc text before dispatching.
- Styling reuses the existing `workbench-theme.css` variables via a small CodeMirror theme.

- **Alternative considered:** `@uiw/react-codemirror` wrapper — rejected; one more dependency for
  ~40 lines of ref-and-effect code, and the workbench needs precise control of state resets.

### 7. Cursor extension — build-time copy of shared artifacts

`packages/vscode` (private) contains only `package.json` (with `contributes.languages` +
`contributes.grammars`) and a trivial sync script that copies the grammar and language
configuration from `packages/language/grammars/` into the extension folder before use. VS Code
requires `contributes` paths to live inside the extension directory, so a copy (checked by the
build, regenerated on demand) beats a fragile relative path outside the folder.

Install: `ln -s "$(pwd)/packages/vscode" ~/.cursor/extensions/silk-effect.silk-language-0.0.0`,
then reload Cursor. Documented in the package README.

- **Alternative considered:** symlinking the grammar files into the extension — symlinks inside a
  symlinked extension are unreliable across editor updates; a copied file plus a freshness check in
  the test suite is boring and works.

## Risks / Trade-offs

- [Full re-lex on every keystroke] → Irrelevant at workbench scale; `ponytail:` comment marks the
  incremental-lexing upgrade path.
- [Copied grammar in `packages/vscode` drifts from the source grammar] → Test asserts byte-equality
  of the copies; sync script regenerates.
- [Token-level highlighting only — identifiers all look alike (no function-name vs type coloring)]
  → Accepted ceiling of the lexer-driven approach; a future tree-sitter/Lezer layer can add
  structure if ever wanted.
- [CodeMirror in the docs bundle grows the labs page] → CodeMirror core is ~120 KB min; labs is
  already a heavy interactive page and Next code-splits per route.
- [Byte↔UTF-16 mapping bugs corrupt highlights or the span cursor] → Covered by dedicated
  non-ASCII scenarios in both the extension tests and the spec.

## Open Questions

None — remaining choices (exact scope names in the tmLanguage, CSS class names) are cosmetic and
decided during implementation.
