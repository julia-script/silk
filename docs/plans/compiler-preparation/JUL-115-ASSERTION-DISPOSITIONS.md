# JUL-115 evaluator and direct-Wasm assertion dispositions

This ledger freezes every affected test registration found at implementation start
`ee6ebb3d41a55fee65f1119b9c495c16d8dfec09`. Locations are baseline locations and remain
stable evidence even where the source file was subsequently deleted.

The Claim column transcribes the baseline assertion's role, so it intentionally names removed
engines where those engines were part of what the old assertion observed. The Disposition and
Surviving evidence columns state the destination; no baseline engine name implies a retained API
or compatibility contract.

Disposition meanings:

- **Retain:** an already-surviving authoritative assertion proves the claim.
- **Rewrite:** the obsolete execution leg was removed and the same suite retains structural compiler evidence.
- **Corpus:** runtime behavior is consolidated into the independently pinned native acceptance corpus.
- **Delete:** the claim specified the removed evaluator, direct emitter, parity machinery, or host boundary.

Final assertion count: 897 (28 Retain, 289 Rewrite, 309 Corpus, 271 Delete).

Corpus rows deliberately share cases: the migration policy requires the smallest authoritative
runtime corpus, not one native compilation per former feature test. `DriverNativeAcceptance`
compares process results directly with each case's pinned `expected` value and proves exact CI
shard coverage. Compile-time behavior remains covered only by `StaticEvaluation` tests.
