# Stack VM pressure findings

The VM uses the same stable categories as the lexer and explicitly compares repeated evidence. A
repeated inconvenience is evidence for a focused proposal, not an automatic choice of syntax or
library shape.

| Category | Finding | VM evidence | Lexer comparison | Disposition |
| --- | --- | --- | --- | --- |
| Language | The eight numeric opcodes want a closed named-value vocabulary. Their raw `u8` representation remains useful at the bytecode boundary, but dispatch needs reusable names independently of enum cases. | Opcode constants and dispatch tests throughout `main.silk`, plus the centralized `OPCODE` mapping in `StackVmPressure.test.ts` | Independently confirms the lexer's 67 numeric token kinds. Two unrelated programs justified separating typed scalar constants from the larger enum/exhaustiveness design. | Completed as literal-only, explicitly typed scalar constants. Opcodes, limits, and diagnostic codes now use ordinary declarations with no runtime storage or VM recognition. |
| Standard library | A consumer cannot currently read the ordered `Vector<Step | VmDiagnostic>` event stream. `Vector.get` requires exclusive access, and its Copy path lowers structural-union elements through `Slot.copy`, which fails MIR provenance verification. The VM therefore records exact observations and its fingerprint when each event is appended. | `pushStep`, `pushDiagnostic`, and `fingerprint` in `main.silk`; the rejected read-back implementation produced `SlotCopy lost its slot, element, value, or result provenance` | Confirms the lexer's need for a shared read surface, while narrowing it: shared reads of ordinary Copy elements are independently justified, but structural-union reads also require a compiler-level union-copy repair. | Defer a focused shared-Vector-read proposal with an honest element boundary; do not claim general union reads yet. |
| Compiler defect | Dynamic indexing into a fixed array works for a direct local, but the same indexed place nested below `&mut Machine` was unavailable during elaboration and the backends only encode static reference-place selectors. Flattening the machine state into locals kept the VM ordinary and executable. | The accepted `stack[depth]` operations in `execute`; the rejected `machine.stack[machine.depth]` implementation stopped at an unavailable nested reference place | New evidence; the lexer did not require mutable indexed storage behind a struct reference. | Deferred as a general nested dynamic-place compiler repair, not worked around with a VM primitive. |
| Compiler defect | The first two-vector VM corrupted the diagnostic Vector's union tag natively, but focused characterization proved ordinary multi-affine calls and returns are sound. The real defect was path-insensitive address-root bookkeeping: merely emitting an exclusive diagnostic borrow on a malformed branch caused the valid branch to reload uninitialized private storage after a later call. | The accepted ordered event stream avoids the dormant diagnostic root; `MultiAffineReturn.test.ts` reconstructs the original two-vector VM, and LLDB localized the former SIGTRAP to `Vector<VmDiagnostic>.drop` after an untaken borrow branch | New evidence; the lexer borrowed both result vectors on its successful observation path, so its native address storage was initialized at runtime. | Repaired by making LLVM address-root storage valid on every path and synchronizing roots at definition; evaluator, native, Wasm, and fresh-process artifacts agree. |
| Compiler defect | Copying a structural-union element out of `Vector` loses `Slot.copy` provenance in MIR verification. Append-time observation avoids the copy but does not repair it. | The rejected event read-back path and the verifier diagnostic `SlotCopy lost its slot, element, value, or result provenance` | The lexer only read nominal Copy records, so it exposed the exclusive borrow but not structural-union copying. | Deferred as a compiler correctness issue distinct from the public Vector borrow surface. |
| Tooling / ergonomics | Numeric opcode literals made dispatch and jump-test source harder to navigate than the TypeScript reference mapping; go-to-definition could not answer what `6` meant. | Side-by-side `main.silk` opcode branches and the named `OPCODE.jumpIfNonZero` reference | Independently confirms the lexer's numeric token-code navigation problem. | Completed: constant references expose semantic occurrences, presentation, completion, hover, and navigation through the same declaration identity used by local and imported values. |
| Performance / cost | Dispatch is a visible linear chain over eight opcodes, while the fixed operand stack allocates nothing and only the pay-for-use event stream grows. The allocation-pressure case crosses multiple growth ordinals and every failed ordinal cleans up across all engines. | Dispatch in `execute`, general-operation MIR assertions, allocation sweep, and evaluator/native/Wasm gates | Like the lexer's keyword chain and element-wise Vector migration, the costs are explicit rather than hidden behind runtime machinery. | Accept for bootstrap correctness. Benchmark before proposing dispatch tables, bulk moves, or VM intrinsics. |

The VM confirmed two lexer findings strongly enough to shape focused work. Typed scalar constants
are now complete and name opcodes, limits, and diagnostic codes without runtime storage. The
apparent native multi-vector ABI defect was repaired as path-insensitive address-root
materialization instead; the natural two-vector VM now runs without changing aggregate transport.
Shared Vector reads remain the next evidence-backed library/compiler boundary, not an implied
self-hosting sequence.
