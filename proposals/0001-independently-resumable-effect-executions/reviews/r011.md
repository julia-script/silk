## Dedicated simplification

### Material

1. Remove `drive` result generic `B` and make both outcome callbacks and `drive` return unit.
2. The reviewer proposed replacing endpoint state `O` plus reusable `R(&O)` with one detached
   capturing `N: fn() -> ()`.

### Synthesis of the endpoint proposal

The second item is not a valid same-language reduction. In current Silk, a reusable shared `fn` can
borrow separately owned non-Copy state; a partial application that owns an affine argument is a
consuming `once fn`, while capturing a loan would fail `Intrinsic.Detached`. `O` plus `R(&O)` is the
existing exact-callable shape that both owns affine routing state and permits repeated notification.
Collapsing it would require a new closure/callable capability, so it does not preserve the selected
surface assumptions.

### Smaller alternatives with exact losses

- A step-result sum loses the post-`onSuspend` notification commit point unless another operation or
  state is added.
- Eager start loses owner-selected first activation and never-started drop.
- Dormant sweeping loses task-specific O(1) push readiness.
- Runtime-funded packaging loses recoverable admission, rollback, pooling, and accounting.
- Trusting `G` for late-Wake safety makes stale source registration memory-unsafe.
- Removing `Intrinsic.Detached` admits escaping loans or makes generic wrappers invalid.
- Ordinary callback storage requires broader existential callable support.
- A second wake allocation loses the selected one-package contract.
- `Execution<()>` only forces source result storage for non-Fiber owners.
