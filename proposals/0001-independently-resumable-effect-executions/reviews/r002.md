## Scope and language coherence

### Findings

No material scope or coherence finding remains from r001.

The proposal now selects one explicit erasure boundary with a defensible ownership rule:
`Intrinsic.execution` consumes a closed Effect whose exact representation retains no lexical loan.
Owned captures and owned provider values may move into the opaque execution; borrowed values and
providers may not. The illustrative Fiber wrapper does not quietly weaken this rule by inheriting
the borrowed Scheduler. It uses Scheduler only to insert the already closed execution and leaves
automatic provider inheritance to the canonical concurrency-library proposal.

This is a meaningful restriction, but it is coherent with the proposal's scope. The SLP enables
ordinary-source fibers; it does not promise a final Fiber API, nested-fork inheritance, scoped
children, or arbitrary detached borrows. Those policies can be added without changing the selected
continuation, drive, park, and destroy powers.

Browser-Wasm completion is now correctly absent from the claimed feature. A park-capable source root
requires a compatible target owner, while asynchronous exported-root ABI and eventual outcome
delivery are named future host-integration work. The root timer remains a conditional lowering
pressure case rather than evidence that this SLP defines browser execution.

### Proposed split, if any

No further split is recommended. The existing separation among execution/parking, local shared
ownership, canonical concurrency policy, scoped fibers, parallel execution, and host integration is
cohesive.

## Examples and programmer model

### Findings

The r001 examples blockers are resolved:

- Scheduler, Deferred, task-node, and join-result construction expose ordinary
  `? &mut Allocator ! OutOfMemoryError` rows. No Scheduler arena is introduced merely to hide those
  rows.
- Joinable fork allocates observable result state; resultless infallible spawn does not. A task node
  reserves its ready-link storage, so wake and join do not acquire surprise allocation effects.
- `TaskStore.takeReady` returns an option and `driveOne` discards stale queued identities.
- A never-driven execution cleans its closed body and owned captures without invoking drive
  callbacks.
- The complete `onSuspend` invocation returns before `onReady` may run. If `onSuspend` destroys the
  execution after an early wake, cancellation wins and `onReady` is not invoked.

The witness intentionally accepts closed child Effects. This means it demonstrates the compiler
substrate and one complete fork/wait/wake/join path, not automatic Scheduler or arbitrary service
inheritance. The prose labels that boundary clearly enough that it is not a hidden limitation.

### Missing or corrected cases

No material case is missing for this proposal. A future concurrency-library SLP should pressure:

- owned versus scoped provider inheritance for nested Fiber operations;
- task-store shutdown and supervision policy;
- reusable task-node and ready-link cleanup after success, cancellation, and source failure; and
- the API distinction among joinable fork, resultless spawn, supervised spawn, and daemon tasks.

Those cases choose library ownership policy rather than add a compiler primitive here.

## Compiler privilege and realizability

### Findings

The callback-shaped surface is now sound at the abstraction level selected by the proposal. Each
park activation has a stable compiler/runtime wake-control cell. Execution destruction cancels the
cell before frame cleanup and releases `onReady`; an externally retained one-shot callback owns only
its inert cell reference and becomes a safe no-op. Arbitrary `G` cleanup may unlink source resources
promptly but is not trusted for memory safety.

The cell also closes the early-wake race: readiness is latched until the complete `onSuspend`
callback returns. The owner cannot drive concurrently because `drive` consumes the only affine
execution handle, and completion never returns one. Never-driven, dormant, ready-but-undriven, and
completed paths each have one stated cleanup authority.

Compiler/runtime control storage remains distinguishable from ordinary source allocation.
Execution and wake-header storage may be pooled, split, or grown by a target, with fatal exhaustion
matching the existing suspension-frame substrate. Source Scheduler, Deferred, result, and task
state uses the explicit Allocator contract from SLP-0002. No compiler-known library actor is needed.

The explicit `Intrinsic.execution` call is the operation that erases one exact owned Effect
representation into a uniform opaque handle. That is not the implicit representation joining
forbidden by [generics, interfaces, and specialization](../../../docs/language/generics-interfaces-and-specialization.md). Realization must store or generate the concrete layout, resume, and cleanup
metadata behind that sealed boundary without making it a public callable/Effect coercion.

### Smaller boundary, if any

No smaller sound boundary was found. Removing affine `Execution` loses dormant ownership and exact
destroy. Separating registration from park reintroduces lost notification. Removing the stable wake
cell makes late callbacks unsafe. A public Wake, execution-step sum, explicit destroy, compiler
Scheduler, or universal coroutine would add source surface without enabling a driving case that the
selected three operations cannot express.

## Synthesis

### Proposal-level blockers

None.

### Editorial improvements

None required before another fixed review. OpenSpec should preserve the distinction between the
semantic callback contract and each target's concrete callable/control-cell representation.

### OpenSpec realization questions

- Define the execution state machine across constructed, running, dormant, eligible, completed, and
  destroyed states, including diagnostics for illegal source constructions and unsafe corruption.
- Reuse exact Effect capture facts to reject every retained value or provider loan at
  `Intrinsic.execution` while accepting owned captures with deterministic cleanup.
- Specify wake-cell reference ownership, early-wake latching, cancellation-before-cleanup, late
  no-op behavior, and the future atomic transition obligations without imposing atomics locally.
- Prove cleanup tables for never-driven, normal completion, dormant destruction, eligible
  destruction, and registration-guard cleanup.
- Preserve direct, nested-only, and independently resumable pay-for-use tiers across evaluator,
  native, and Wasm.
- Prove that TaskNode, ready-link, Deferred, result, and queue allocation remains ordinary source
  behavior and that no Scheduler, Fiber, Deferred, timer, Coroutine, or Allocator is recognized by
  spelling.

### Reviewer disagreements

None material. The main pressure point is whether closed child Effects are sufficient evidence for
"enabling fibers." They are sufficient for this compiler-substrate SLP because the witness performs
fork, wait, wake, join, destruction, and typed result publication. They would not be sufficient for
a canonical Fiber API proposal, which must separately select provider inheritance and structured
lifetime policy.
