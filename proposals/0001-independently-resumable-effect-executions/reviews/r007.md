## Scope and language coherence

### Findings

#### S1 — Initial Execution needs an explicit cohesion argument

The proposal identifies the current wall as ownership of an unfinished computation after it
relinquishes, but it also selects a type-erased never-started container, its invoke/drop metadata,
and never-driven cleanup. A non-suspending body can be packaged and dropped without ever creating a
continuation. The scope lens proposed shrinking the primitive so first activation consumes exact `F`
directly and produces opaque `Execution<A>` only if it parks, or splitting owned erased Effects into
another SLP.

The smaller operation is insufficient for the stated owner-neutral source construction. It forces
every wrapper to run a heterogeneous child immediately to its first completion or park because
ordinary source cannot store distinct exact Effect representations in one task store. That chooses
eager first activation at the compiler boundary. Initial Execution instead gives the same affine
owner control of first and later activation; eager policy remains expressible by immediate drive.
Revision must make that necessity a driving example and scope-cohesion argument rather than relying
only on the Fiber witness's enqueue behavior.

#### S2 — The Timer case still crosses the split root boundary

The Scheduler owns the delayed child, but not the parent executing `Fiber.join`. Once the immediate
child completes, the delayed child parks, and no task is ready, `Fiber.join` calls
`Scheduler.awaitReady`, which parks the parent. A natural complete-entry call therefore requires the
implicit root owner moved to Draft SLP-0003. All three lenses that discussed this case agreed.

Required revision: explicitly construct an outer Execution for `concurrentTimer`, close its
Scheduler/Allocator requirements with owned providers, and state that some source driver owns and
redrives it without itself parking. Alternatively make the result conditional on SLP-0003 and stop
using it as independent SLP-0001 evidence. The boundary case must name `concurrentTimer`, not only
`delayedValue`.

#### S3 — The nested-join example creates a strong ownership cycle

Revision 23 moved `LocalScheduler.clone` into a child retained by the same Scheduler's TaskStore:

```text
TaskStore -> outer Execution -> captured LocalScheduler -> Shared<TaskStore>
```

SLP-0002 has neither Weak ownership nor cycle collection, so scheduler shutdown cannot reach last-
handle cleanup. This is exactly the cycle the witness elsewhere claims to avoid.

Required revision: remove nested join from the completed Shared-only witness and show it rejected
while Scheduler and Allocator requirements remain open. A dependent concurrency proposal may supply
a cycle-safe child capability, Weak ownership, scoped children, or a different join architecture.

### Proposed split, if any

No further split is required. Initial state is cohesive if owner-selected first activation is made
part of the execution-lifecycle thesis. The linked SLP-0003 boundary and dependency direction are
otherwise coherent.

## Examples and programmer model

### Findings

#### E1 — The “ordinary-source” witness uses source forms Silk does not have

Revision 23 used anonymous `fn(...) { ... }` expressions even though current Silk constructs
captured callables from named functions and trailing partial application. It also used named `union`
declarations although Silk has nominal structs and structural unions, `Bool` rather than `bool`,
commas after struct fields and match arms, and `once` on ordinary affine parameters rather than only
callable/Effect access.

Required revision: replace callbacks with named functions whose captured arguments are the trailing
suffix, wrap each structural union in ordinary nominal structs, use current scalar and punctuation
syntax, and let affine values be consumed through plain nominal parameters plus `move` at calls.

#### E2 — Several effects discard or propagate values through nonexistent APIs

The Timer example implicitly discarded the immediate child's `i32`; `driveOne` ignored a non-unit
drive outcome; and `Fiber.join` called nonexistent `Effect.fromResult`.

Required revision: use explicit `drop`, bind or drop the drive outcome, and define an ordinary local
effect helper that matches `Result.Success`/`Result.Failure`, returns the value, or uses `fail`.

#### E3 — TaskReservation rollback is asserted but not represented

`reserveTask` occurs before separately fallible execution-package construction. The prose claims
that a later failure cleans the reservation, but the witness gave `TaskReservation` no owned fields,
uncommitted state, Drop behavior, or disarm transition.

Required revision: state that reservation performs all fallible capacity/readiness allocation before
publication, owns both reserved slots and the readiness Allocation through an affine rollback guard,
rolls them back on drop, and is consumed/disarmed by infallible `enqueueNew`.

### Missing or corrected cases

- Timer notification must be delivered by a same-thread reactor/poll turn because Wake is initially
  non-transferable. Moving Wake to an OS callback thread is a rejected boundary until the parallel
  memory proposal.
- Coroutine resume must continue to consume its retained Wake before each post-yield drive.
- Nested join must be shown as rejected, not made cycle-safe through a strong Scheduler clone.

## Compiler privilege and realizability

### Findings

No additional material primitive blocker was found after accounting for S1. The compiler lens
accepted the SLP-0003 split and `Intrinsic.Detached` direction but identified realization contracts
that must remain normative at OpenSpec handoff.

### Smaller boundary, if any

Manufacturing Execution only after first park removes Initial state but also removes owner-selected
deferred start for heterogeneous tasks. Revision 24 directly rebuts that subtraction with the first-
activation example; no general erased callable or task type is added.

### OpenSpec realization requirements

- Define a target-neutral per-Execution context owning stack head/segments, logical depth, growth
  state, and destroy root. Alternate two executions in non-LIFO order on evaluator, native, and Wasm,
  while proving nested-only code keeps its cheaper current LIFO/global path.
- Derive `Intrinsic.Detached` from the exact executable realization environment and owned-provider
  captures, not from Effect success/failure semantic types. Cover borrowed and owned providers,
  nested nominal loans, and opaque producer results.
- Exercise at least one native and one Wasm same-thread system-event path, and reject worker-thread
  delivery while Wake remains non-transferable.

## Synthesis

### Proposal-level blockers

1. Timer's joining parent had no explicit owner after the root split.
2. Nested Scheduler inheritance created an uncollectable Shared strong cycle.
3. The ordinary-source sufficiency witness used invalid callable, union, parameter, discard, and
   Result APIs.
4. Reserved-but-uncommitted task storage lacked a rollback lifecycle.
5. Initial Execution's policy-neutrality necessity was implicit rather than defended.

### Editorial improvements

- Remove the claim that non-effectful `onReady` can immediately drive: it receives neither Execution
  nor an Effect context and can only publish readiness for a later owner Effect.
- Use `bool`, plain affine parameter types, explicit discards, and comma-free current Silk bodies.

### OpenSpec realization questions

- Execution-relative stack/context ownership across evaluator, native, and Wasm.
- Exact-environment derivation and generic propagation of `Intrinsic.Detached`.
- Same-thread event delivery under the initial non-transferable Wake model.

### Reviewer disagreements

The scope lens classified Initial pre-start erasure as a separate thesis and proposed a split or
park-only handle. The synthesis rejects that subtraction because it forces eager child activation
and prevents ordinary-source storage of heterogeneous deferred tasks; Revision 24 adds the missing
driving evidence and cohesion argument. Reviewers otherwise agreed on the Timer boundary,
nested-provider cycle, and impossible immediate-drive claim.
