## Compiler privilege and realizability

### Material

1. Ordinary `fn` syntax does not prove that a callback cannot run a closed Effect which reaches
   external parking. A registration callback can recursively park while the outer park is
   Registering, and an erased endpoint callback can make `wake` unexpectedly park-capable. The
   runtime-invoked callbacks need a normative no-external-park admission fact.
2. The proposal marks an execution Eligible before invoking `R(&O)`. Detached endpoint state can
   indirectly reach Shared state containing that Execution and reentrantly drive it while the prior
   generation's invocation retain is live. A notification-phase drive exclusion is required.

### Editorial

- Replace “non-effectful callback” with the actual enforced no-external-park rule.
- Define a “later Eligible drive” as one occurring after endpoint callback return.

### OpenSpec-safe

The internal encoding of Notifying, DestroyPending, generation counters, retains, dispatch IDs,
execution-stack segments, pooling, and diagnostics remains safely deferrable. Existing compiler
facts make evaluator, native, and Wasm realization feasible.
