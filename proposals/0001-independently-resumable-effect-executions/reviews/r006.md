## Scope and language coherence

### Findings

#### S1 — Root execution ownership remains a distinct language/target contract

Revision 22 made synchronous target entry a complete root owner: it constructs the root Execution,
owns its exceptional storage, drives it, waits or polls after parking, and rejects an unsupported
target after specialization. That is internally understandable, but it combines two independently
decidable contracts:

1. explicit owner-neutral Execution plus park/wake, used by ordinary-source schedulers; and
2. an implicit target-owned adapter that turns a complete Effect entry into such an Execution and
   provides its wait/poll and storage policy.

The second contract is not needed to prove that ordinary source can build fibers once an execution
owner exists. Conversely, a target entry needs host/target validation and lifecycle rules that do
not follow from the six selected intrinsics.

This is the same scope objection raised against revisions 20, 21, and 22. Revision 20 removed a
browser-specific ABI, revision 21 added target rejection and a cost tier, and revision 22 selected a
full synchronous entry owner. Those revisions improved the model but did not remove the independent
decision. Under the convergence procedure, an objection surviving three consecutive revisions is
an author decision fork rather than another autonomous revision target.

Smaller split: keep explicit Execution and external parking in SLP-0001; define the implicit
synchronous target-entry adapter in a dependent proposal. The eventual source API can still be
ordinary `run program() |> Effect.provideMut(...)`; the split does not require a public executor or
special run method.

#### S2 — Unresolved direct dependencies are not all acceptance gates

The proposal depends directly on [values and types](../../../docs/language/values-and-types.md), [generics, interfaces, and specialization](../../../docs/language/generics-interfaces-and-specialization.md), [unsafe code, intrinsics, and targets](../../../docs/language/unsafe-intrinsics-and-targets.md), [runtime and standard-library boundary](../../../docs/language/runtime-and-standard-library.md), [Effect suspension](../../../docs/language/effect-suspension.md), and SLP-0002,
but names only [generics, interfaces, and specialization](../../../docs/language/generics-interfaces-and-specialization.md) and SLP-0002 as acceptance gates. In particular, a change to [unsafe code, intrinsics, and targets](../../../docs/language/unsafe-intrinsics-and-targets.md)'s
sealed-intrinsic authority or [runtime and standard-library boundary](../../../docs/language/runtime-and-standard-library.md)'s Effect/lowering boundary could change this proposal's
privilege and construction claims. Every unresolved direct dependency must either gate acceptance
or have the exact imported decision restated so that later movement cannot silently alter this
Candidate.

### Proposed split, if any

Split only the implicit synchronous target-root adapter. Do not split the explicit Execution,
park/wake handshake, or ordinary-source scheduling sufficiency witness.

## Examples and programmer model

### Findings

#### E1 — Safe generic construction cannot state its detachability precondition

The witness declares `Execution.make<A, F: once Effect<A>>` as an ordinary safe generic wrapper,
but the unsafe initializer requires the concrete `F` representation to retain no lexical or
provider loan. Under [generics, interfaces, and specialization](../../../docs/language/generics-interfaces-and-specialization.md), a generic body is checked once from its declared bounds; a later
specialization cannot introduce a hidden well-formedness condition. Therefore the wrapper either
cannot prove its assertion or unsafely accepts a borrowed capture such as:

```silk,ignore
fn borrowed(value: &i32) -> once Effect<i32> {
  return effect { return value }
}

let value = 42
let invalid = run Execution.make(borrowed(&value))
```

The proposal must select an expressible compiler-owned detachable/owned-environment constraint, a
sealed safe initializer with defined generic admission semantics, or a larger scoped Execution
model. This applies equally to retained generic callback environments. Marking the wrapper unsafe
does not solve the lifetime proof.

#### E2 — The witness confuses a Scheduler service key with a concrete provider

`Scheduler` is declared as a struct but used as a requirement key and queried through a nonexistent
`Scheduler.service()` conversion. A coherent witness needs a `service Scheduler`, a distinct
concrete provider such as `LocalScheduler`, and direct ambient service operations. Application code
must provide a borrow explicitly:

```silk,ignore
let mut scheduler = run LocalScheduler.make()
return run program()
  |> Effect.provideMut<Scheduler>(&mut scheduler)
```

Likewise, a detachable child that needs Timer or Scheduler behavior must receive an owned concrete
provider with `Effect.bindRequirementOwned`; pipeline syntax does not implicitly borrow or convert
an owned provider.

#### E3 — Mandatory readiness packaging contradicts the non-parking cost tier

The selected `drive` operation always consumes an Allocation matching `readyLayout<R>`, including
for an execution that completes on its first drive without parking. Because `Execution<A>` erases
the body's suspension summary, the caller has no selected way to omit the wake-control cell and
retained callback package. The proposal must either state honestly that every explicit drive pays
readiness packaging, with retention only on actual park, or add a statically non-parking drive path
or indexed capability. The current matrix promises neither continuation nor wake state for that
case and is not implementable by the selected surface.

### Example and editorial corrections

- The Coroutine pressure case must show each `resume` consuming the Wake retained by the previous
  yield before redriving the now-Eligible execution; direct drive of Dormant is a fatal trap.
- A nested-join example must move owned Scheduler and Allocator providers into the child and show
  that a later waiter-allocation failure becomes the child's typed result.
- The Timer example must either state that registration capacity was pre-reserved and infallible or
  show fallible preparation before the non-effectful `park` registration callback.
- `Updated` remains 2026-08-21 although revisions 20–22 and their reviews are dated 2026-08-22.

## Compiler privilege and realizability

### Findings

#### C1 — One affine readiness Allocation cannot support the promised cancellation lifetime

Revision 22 places both the stable wake-control cell and retained `R` environment in one readiness
Allocation. It also releases that Allocation when `onSuspend` destroys the execution while allowing
a Wake retained elsewhere to remain safe and become a no-op. An Allocation is one indivisible
affine reclaim ticket: releasing it makes the late Wake a use-after-free, while retaining only a
small header is not expressible.

The smaller coherent contract is to retain the whole readiness Allocation until Execution, Wake,
and transient registration/notification ownership are all gone. Destruction may drop `R` promptly,
but cannot release the allocation while a late Wake exists. A split control-cell/callback allocation
is possible but adds another procurement and ownership contract.

The same handoff also fails to structurally enforce “cannot resume inline.” Passing the Allocation
to `R` while notification still uses its cell creates competing authority; moving `R` and severing
the cell first permits the callback to redrive immediately unless that is an explicit unsafe caller
obligation. The proposal must select one ordering and weaken the incompatible claims.

### OpenSpec realization requirements

- Replace the current single suspension summary with a capability lattice that distinguishes direct,
  nested-only suspension, and externally parkable execution, with a verified construction delimiter.
- Partition evaluator state into execution-local control state and legitimately shared process state
  so interleaving cannot contaminate call depth, traces, stack accounting, or pending transfers.
- Give native and Wasm explicit executions execution-relative stack roots and state-indexed dormant
  destruction while preserving the current cheap LIFO path for nested-only suspension.
- Preserve normative lifecycle scenarios for early wake, late wake, destruction before wake,
  reentrant destruction, stale ready tombstones, readiness-package reuse, rollback, and loan cleanup.

## Synthesis

### Proposal-level blockers

1. **Author scope decision:** whether implicit synchronous target-root ownership belongs in this SLP
   or a dependent one. The same objection has survived three consecutive revisions.
2. **Generic admission:** ordinary generic wrappers cannot express the no-external-loan condition
   required by detached execution and retained callbacks.
3. **Readiness ownership:** one affine allocation cannot be promptly released while an externally
   retained cancelled Wake remains valid, and the selected notification handoff does not enforce
   its claimed no-inline ordering.
4. **Cost contract:** mandatory readiness packaging conflicts with the selected non-parking explicit
   Execution tier.
5. **Source witness:** Scheduler/Timer provider closure uses source operations and ownership
   conversions Silk does not have.
6. **Dependency authority:** not every unresolved direct dependency is currently gated or restated.

### Reviewer agreement and disagreement

All three lenses found material issues. The scope lens required the root split; this is the third
consecutive round containing that objection and therefore triggers the procedure's decision-fork
stop. The examples and compiler lenses independently agreed on the missing generic detachability
contract and found distinct source-witness and readiness-storage contradictions. No reviewer found
revision 22 clean.

## Revision response

Resolved in Candidate revision 23 after the author selected the recommended scope split:

1. Created linked Draft SLP-0003 for implicit synchronous program-entry ownership, storage, target
   validation, and final-outcome adaptation. SLP-0001 now stops at explicit owner-neutral
   Executions; the child preserves ordinary `run` as its desired source experience.
2. Added the compiler-owned static `Intrinsic.Detached` property to the generic contracts for body
   and retained-callback representations. Safe wrappers declare the property, so open generic bodies
   check once and borrowed concrete captures fail at the ordinary construction boundary.
3. Retained the complete indivisible readiness Allocation behind a cancelled outstanding Wake.
   Live notification now moves out `R`, establishes Eligible, severs the cell, ends transient access,
   and only then invokes `R` with the unique Allocation ticket. The intrinsic does not drive from
   Wake; immediate redrive, if desired, is explicit owner policy.
4. Made the cost matrix state that every explicit drive supplies a readiness package, even when the
   execution cannot park. Immediate completion returns it unused and activates no Wake or
   continuation state; no additional capability-indexed drive operation was added.
5. Replaced the witness's Scheduler struct/service conflation with a `service Scheduler`, distinct
   `LocalScheduler` provider, direct ambient operations, and explicit service-key provision. Added
   owned Timer and nested Scheduler/Allocator provider binding, fallible Timer preparation,
   Coroutine Wake handshakes, and nested-join failure accounting.
6. Made every unresolved direct dependency an acceptance and implementation-handoff gate, and fixed
   the stale update date.
