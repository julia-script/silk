## Scope and language coherence

### Findings

#### S1 — Three independently outcome-capable theses remain bundled

Revision 26 explicitly acknowledges that first activation, push readiness, and caller-funded fixed
storage are independently subtractable and can reach coherent language outcomes. That admission
meets `PROCESS.md`'s split criterion; calling the combination one Scheduler-grade point or binding it
through one initializer does not make the outcomes interdependent.

Concrete coherent combinations include:

- heterogeneous deferred first activation plus O(1) Wake readiness with fatal runtime packages;
- Initial Execution plus recoverable storage with legal owner sweeps and no Wake; and
- eager start plus push readiness and recoverable readiness storage.

This objection has now survived r008/Revision 24, r009/Revision 25, and r010/Revision 26. The author
already selected the richer overall capability direction, but proposal identity still determines
whether each conceptual thesis can independently reach Accepted, Deferred, or Declined.

### Proposed split, if any

1. **Execution ownership and activation** — a closed detached Effect becomes an affine owner-held
   Execution before first activation versus only after first relinquishment. Driving case:
   heterogeneous enqueue and never-started drop.
2. **External parking and readiness** — task-specific Wake push notification versus legal owner
   sweeping or another readiness contract. Depends on the selected execution lifecycle. Driving
   cases: Deferred, explicit Timer/reactor, cancellation, and large dormant sets.
3. **Execution-package procurement** — caller-funded recoverable execution/readiness packaging
   versus runtime-owned fatal exhaustion, including combined versus separately reclaimable packages.
   Depends on the layouts selected by the first two decisions. Driving case: bounded admission and
   rollback.

The compiler implementation may share continuation, liveness, cleanup, and layout machinery across
all three proposals. Shared realization does not combine their language outcomes.

## Compiler privilege and realizability

### Findings

#### C1 — Non-parking Execution still pays an unearned endpoint package

A statically non-parking Execution must accept endpoint state and allocate readiness storage even
though its first-activation case needs only erased Initial ownership. Because that allocation can
fail observably, optimization cannot remove it while preserving semantics.

Required resolution: the ownership/activation proposal needs an endpoint-free admission path. The
parking proposal should add the endpoint only when its capability is selected.

#### C2 — One caller-funded package is a smaller untested model

One exact layout over `F`, `O`, and `R` can place body ownership, wake cell, and fixed endpoint in one
Allocation. It preserves recoverable pre-publication procurement, O(1) notification, allocation-free
park/wake, late-Wake safety, and exact value cleanup.

Exact loss: after cancellation, an outstanding Wake retains the entire inert combined package
rather than only the smaller readiness package; independent pools and prompt reuse of execution
bytes are unavailable. The Candidate supplies no pressure case selecting bounded late-Wake
retention, so two Layout operations and two allocation failure points remain unearned. This belongs
in the procurement thesis after execution and parking layouts are known.

#### C3 — `park` need not return registration state

Every selected wrapper immediately drops the `G` returned by `park`. The compiler already retains
and destroys `G` while dormant. A smaller contract returns unit: on resumption the runtime drops `G`
immediately before continuing, and dormant destruction also drops it.

Exact loss: resumed source cannot inspect `G`, delay cleanup, recover an affine resource from it, or
perform a later explicit close. No driving case requires that power. The external-parking thesis
should either subtract the result or add a counterexample that earns post-resume guard ownership.

### Smaller boundary, if any

The dedicated simplifier found the attach-once endpoint minimal for task-specific push readiness:
removing it loses targeted notification, installing it per drive adds retargeting and repeated
erasure, and installing it lazily introduces a hidden/fatal allocation or fallible parking handshake.
The affine drive branch state is likewise minimal for callback-shaped handoff without a sealed step
sum or duplicated/shared owner state. The remaining reductions are endpoint-free non-parking
admission, unit-returning park, and a one-package procurement candidate.

2. Non-parking Execution pays an endpoint allocation that belongs only to the parking capability.
3. One combined caller-funded package is not compared with two separately reclaimable packages.
4. Returning arbitrary `G` from park is unearned by every selected example.

## Revision response

Revision 27 resolves the material technical findings while retaining one cohesive Candidate:

1. The author rejected the proposed three-way organizational split. First activation, readiness,
   and package procurement are selectable design dimensions of one sealed Execution lifecycle, not
   independently useful programmer concepts. Mechanical subtraction can produce alternative
   capability points, but does not by itself satisfy the process criterion for separate proposals.
   Shared ownership and root adaptation remain split as SLP-0002 and SLP-0003 because each introduces
   a distinct source-visible concept with independent use outside this lifecycle.
2. Execution and readiness storage now use one exact combined caller-funded package. The Candidate
   explicitly accepts that a forgotten cancelled Wake retains the larger inert package in exchange
   for removing one intrinsic, one Allocation, and one recoverable failure branch.
3. A statically non-parking wrapper supplies a zero-sized no-op endpoint. Its specialized combined
   layout contains no readiness storage or wake cell, preserving owner-controlled first activation
   without imposing a parking allocation.
4. `park` now returns unit. The compiler/runtime owns registration state `G`, drops it immediately
   before resumed source continues, and also drops it during dormant destruction.
5. The examples now normalize source `TaskReady`/`TaskParked` names against semantic states, make
   drive callbacks return unit, use non-thread-transferable terminology, and separate compile-time
   ownership diagnostics from the Dormant-drive fatal trap and valid cancelled-Wake consumption.

For subsequent convergence rounds, an alternative that removes one selected capability is recorded
as an alternative, not a proposal blocker. A material finding must demonstrate contradiction or
unsoundness, invalid desired source, unrealizability, or a strictly smaller design that preserves
owner-controlled first activation, task-specific O(1) push readiness, and recoverable caller-funded
packaging.
